# benchmark-design — 벤치마크 문법 추출·적용 절차

벤치마킹은 "예쁘다"를 베끼는 게 아니라 **문법(반복되는 규칙)을 추출해 우리 규율과 충돌 없이 이식**하는 것이다. 아래 절차를 고정 순서로 실행한다.

## 1. 입력 확보
- **라이브 사이트**: CDP 헤드리스 크롬으로 실렌더 관찰(스크린샷+computed style 계측). 정지 화면만 보지 말고 스크롤·호버를 실제 트리거.
- **사용자 녹화 영상(.mov 등)**: 즉시 안정 경로에 보존(임시폴더는 만료됨) → `ffmpeg -vf "fps=N,scale=1100:-1"`로 프레임 추출. 정적 구성 분석=1fps, **애니메이션 타이밍 분석=6fps 이상**(프레임 간격=타이밍 해상도). 대형 프레임은 1000px 프리뷰로만 열람(스톨 방지).
- 영상이 무엇을 담았는지 **전제하지 말 것** — 대상 사이트 녹화라고 단정했다가 벤치마크 리서치 영상인 경우가 실제로 있었다. 첫 프레임들로 정체부터 판별.
- 사용자가 영상 말미에 스크린샷을 찍거나 특정 구간을 반복 확대하면 그것이 **가장 강한 지목 신호** — 별도 기록.

## 2. 문법 추출 (6개 렌즈, 각각 근거 필수)
| 렌즈 | 추출할 것 | 근거 형식 |
|---|---|---|
| 설명 방식 | 제목/부제 구조, 부제를 쓰는 조건과 생략하는 조건, 정보 제시 순서(주장→증거→수치→심화) | 프레임 번호 또는 페이지 URL+캡처 |
| 그리드 | 카드 수·폭·간격·라운딩·그림자 유무, 몇 개씩 끊는가, 틴트/배경 교차 규칙 | computed CSS 실측값 |
| 모션 | 등장 방식(페이드/드로잉/스태거), duration·delay·easing 추정, 스크럽형인지 1회 진입형인지 | 프레임 간 diff 또는 transition 계측 |
| 색 | 팔레트가 아니라 **사용 규칙**(주색을 몇 단계로 나누나, 유채색을 어디에만 쓰나) | 색상 실측값+사용처 |
| 타이포 | 크기 위계, 굵기를 위계에 쓰는지 강조에 쓰는지, 국문 줄바꿈 처리 | px/weight 실측 |
| 신뢰 신호 | 법정 표기·연혁·대표 소개·인증 표시 관습(한국 기업 사이트 격식) | 캡처 |

## 3. 적용 매핑표 작성 (스펙 문서 산출)
- 각 패턴 → 대상 사이트의 어느 표면에, 어떤 컴포넌트 수준 지시로 — **구현자가 바로 실행 가능하게**.
- 우선순위: P0(전 페이지 공통 문법) / P1(기존 자산만으로 가능) / P2(신규 자산·오너 확인 선행).
- **충돌 게이트**: 기존 디자인 규율(모션 1종·액션색 1종·간격 기준선), 카피 정책(금지어·오너 게이트), 자산 정책(미확인 사진 게재 금지)과 대조 — 충돌 시 패턴을 기각하거나 변형하고 사유 기록.
- 모션 원리가 기존 체계와 다르면(예: 스크럽 vs 진입형) **구성 문법만 채택하고 모션은 기존 유지**가 기본값.

## 4. 검증
- 적용 후 반드시 실측 재검(visual-qa-prod 스킬): 스펙 수치(스태거 delay·크기·색)가 실제 렌더에서 나오는지. CSS를 넣었다고 끝이 아니다 — transition 단축 속성이 delay를 리셋하거나 specificity에서 지는 사례가 실제로 있었다.

## 산출물
`review/` 또는 지정 경로에 스펙 문서 1개: ①타임라인/관찰 요약 ②문법 6렌즈 ③적용 매핑표(P0/P1/P2+충돌 판정) ④기각 목록(사유). 프레임·스크린샷 근거 없는 항목은 버린다.

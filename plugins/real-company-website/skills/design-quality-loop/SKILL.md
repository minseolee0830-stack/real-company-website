# design-quality-loop — 품질 도달까지 도는 표준 루프

**버전 번호가 아니라 품질 도달이 완료 조건.** 실제 기업 사이트 수준을 목표로 여러 라운드 돌 때의 검증된 절차.

## 0. 지시 분해
사용자 지시에서 ①구체 항목(사진 교체·특정 버그)과 ②전면 검토를 분리 — ①은 정확 수행(임의 확대 금지), ②는 아래 루프.

## 1. 스캔 — 다렌즈 팬아웃 + 적대 검증
- 렌즈 3~4개: AI스러움 체크리스트(/de-ai-website), 벤치마크 격차(/benchmark-design — 실존 기업 재관찰 대조), 모바일 실측, 시각 무결성/페이지 간 리듬.
- 각 발견은 별도 검증자가 반박 시도(실측 재현+기존 규율 충돌 검사) — 확정만 통과. **검증자가 단 단서(fix 교정)를 수정 지시에 반드시 포함**.
- 알려진 대기 항목은 사전 제외 목록으로(소음 제거).

## 2. 수정 — 모델 분담
대규모(다파일)=강한 코딩 에이전트, 중형=중간 모델, 1~2줄=작은 모델. 설계 판단이 크면 먼저 설계 스펙(강한 모델) → 구현(중간 모델, "스펙 이탈 금지").
수정 프롬프트 필수 요소: 확정 발견 전문(JSON), allowed/forbidden 파일, 하드 규칙(새 사실 발명 금지·카피 규칙·디자인 토큰 규율), 검증 목록, "commit 금지"(릴리스는 오케스트레이터 몫).

## 3. 실측 게이트 (/visual-qa-prod)
전체 테스트+프로덕션 빌드+실브라우저 CDP 실측. **FAIL은 먼저 측정을 의심**: 래퍼 vs 실카드 기준, 숨김 요소 매칭, 헤드리스 touchStart의 :active 미발화(mouse.down 대체), 풀페이지 캡처의 리빌 아티팩트. 재측정 후에도 FAIL이면 진짜 결함 → 2로 복귀.

## 4. 도달 판정
판정 스윕: ①핵심만(굳이 없는 말 0) ②AI스러움 0 ③벤치마크 적용도 ④모바일 완성도 ⑤무결성 ⑥"다른 회사에 줘도 말이 되면 실격" 테스트. 미달 → 확정 발견으로 2 복귀. 도달 → 종료.

## 5. 종료
커밋은 오케스트레이터 직접(게이트 수치를 커밋 메시지에). 배포는 라운드별 명시 승인. 배포 후 프로덕션 실측 스팟체크. **사용 중 배운 것은 스킬에 되먹임**(이 문서 포함).

## 하드 레일
- 오너/실무자 원문 카피 불가침(렌더 수정만), 미확인 사진 게재 금지.
- **동일 파일명 자산 교체 금지 — 버저닝(-v2) 필수**(이미지 최적화 캐시가 옛 파일을 서빙하는 실증 사고).
- 모션 1종·액션색 1종 등 확립된 토큰 규율은 라운드가 바뀌어도 유지. dev 서버로 인터랙션 QA 금지.
